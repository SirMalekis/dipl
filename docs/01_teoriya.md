# Теоретическое обоснование и математическое моделирование

## 1. Постановка задачи

Цель этапа — согласовать абстрактные метрики теории графов, применявшиеся в
НИР (доля наибольшей связной компоненты LCC, глобальная эффективность
`E_glob`, взвешенная живучесть `φ_w`), с физическими параметрами
телекоммуникационной сети: пропускной способностью каналов, задержкой
распространения, интенсивностью трафика и требованиями качества обслуживания.

Решаются три задачи:

1. формализовать пороговые требования МСЭ-Т Y.1541 к задержке (IPTD) и
   потерям (IPLR);
2. получить аналитическую связь «пропускная способность — загрузка —
   задержка — потери» на основе теории массового обслуживания (M/M/1);
3. определить QoS-ориентированную нормированную эффективность, которая
   наследует свойства глобальной эффективности, но учитывает физические
   ограничения и отказы узлов.

## 2. Анализ рекомендации МСЭ-Т Y.1541

### 2.1 Классы сетевого QoS

Рекомендация Y.1541 (02/2006) определяет классы QoS 0–5 (таблица 1) и
условные классы 6–7 (таблица 3). Требования задаются для интерфейса
UNI–UNI — между точками измерения на границах сети IP.

| Класс | IPTD, не более | IPDV, не более | IPLR, не более | IPER, не более | Назначение |
|---|---:|---:|---:|---:|---|
| 0 | 100 мс | 50 мс | 1·10⁻³ | 1·10⁻⁴ | VoIP, видеоконференции реального времени |
| 1 | 400 мс | 50 мс | 1·10⁻³ | 1·10⁻⁴ | интерактивные приложения реального времени |
| 2 | 100 мс | — | 1·10⁻³ | 1·10⁻⁴ | сигнализация, транзакции с высокой интерактивностью |
| 3 | 400 мс | — | 1·10⁻³ | 1·10⁻⁴ | транзакционные данные |
| 4 | 1 с | — | 1·10⁻³ | 1·10⁻⁴ | массовая передача данных, видео |
| 5 | — | — | — | — | best effort |
| 6 | 100 мс | 50 мс | 1·10⁻⁵ | 1·10⁻⁶ | условный класс, цифровое ТВ |
| 7 | 400 мс | 50 мс | 1·10⁻⁵ | 1·10⁻⁶ | условный класс, цифровое ТВ |

«—» означает, что требование не определено (в тексте Y.1541 — «Н»).
Для классов 6–7 дополнительно нормируется процент переупорядоченных пакетов
IPRR ≤ 1·10⁻⁶; в данной модели IPRR и IPER не рассчитываются, поскольку
коммутация предполагается без ошибок и переупорядочивания.

### 2.2 Смысл показателей

- **IPTD** — средняя задержка передачи пакета IP, усреднённая по потоку.
  Требование является верхней границей среднего значения, а не максимальной
  задержки отдельного пакета.
- **IPLR** — доля потерянных пакетов. Требование — верхняя граница
  вероятности потери для потока.
- **IPDV** — изменение задержки: разность между квантилем 1−10⁻³
  распределения IPTD и минимальным значением IPTD на интервале оценки.
- **IPER** — доля ошибочных пакетов.

Интервал оценки для IPTD, IPDV и IPLR — одна минута; размер пакета при
оценке — 1500 байт (12 000 бит). Именно это значение используется в модели.

### 2.3 Правила агрегирования по пути

Для пути, состоящего из последовательности звеньев, Y.1541 предписывает:

```text
IPTD_path = Σ IPTD_e                                      (1)
IPLR_path = 1 − Π (1 − IPLR_e)                            (2)
IPER_path = 1 − Π (1 − IPER_e)                            (3)
```

Формула (2) является точной для независимых потерь на звеньях; приближённое
суммирование `Σ IPLR_e` при малых вероятностях даёт близкий, но менее
точный результат. Для IPDV точное агрегирование требует свёртки
распределений; в инженерной модели используется приближение по независимым
дисперсиям:

```text
IPDV_path ≈ sqrt( Σ IPDV_e² )                             (4)
```

Приближение (4) консервативно для оценки сверху при независимых звеньях и
используется только как дополнительный контроль; основные пороги в работе —
IPTD и IPLR, как и указано в постановке задачи.

Путь удовлетворяет классу `K`, если одновременно:

```text
IPTD_path ≤ IPTD_K,  IPLR_path ≤ IPLR_K,  IPDV_path ≤ IPDV_K   (5)
```

Неопределённые требования класса 5 считаются выполненными для любого
достижимого пути.

## 3. Физическая модель звена M/M/1

### 3.1 Допущения

Каждый направленный канал (дуга графа) рассматривается как одноканальная
система массового обслуживания M/M/1:

- заявки (пакеты) поступают пуассоновским потоком с интенсивностью λ;
- время обслуживания распределено экспоненциально со средним `1/μ`;
- буфер ограничен `K` пакетами (модель M/M/1/K);
- потери происходят только из-за переполнения буфера.

Пуассоновский поток является стандартным приближением агрегированного
трафика большого числа независимых источников; экспоненциальное
обслуживание — традиционное допущение теории очередей, дающее замкнутые
формулы и консервативные оценки.

### 3.2 Основные соотношения

Пусть `C` — пропускная способность канала (бит/с), `L` — размер пакета
(бит), `λ_b` — загрузка канала (бит/с). Тогда:

```text
μ = C / L,          λ = λ_b / L,          ρ = λ / μ = λ_b / C     (6)
```

Условие устойчивости очереди:

```text
ρ < 1                                                             (7)
```

Среднее время пребывания пакета в системе (ожидание + обслуживание):

```text
T = 1 / (μ − λ)                                                   (8)
```

Средняя задержка звена складывается из базовой задержки распространения
`d0` (с) и времени пребывания в очереди:

```text
IPTD_e = d0 + 1 / (μ − λ) = d0 + (1/μ) / (1 − ρ)                  (9)
```

Средняя длина очереди и среднее время ожидания:

```text
N_q = ρ² / (1 − ρ),      W_q = ρ / (μ (1 − ρ))                     (10)
```

### 3.3 Потери в M/M/1/K

Вероятность того, что прибывший пакет застанет систему заполненной
(в системе `K` пакетов), равна:

```text
IPLR_e = (1 − ρ) ρ^K / (1 − ρ^(K+1)),   ρ ≠ 1                     (11)
IPLR_e = 1 / (K + 1),                    ρ = 1
```

где `K` — ёмкость буфера в пакетах. Формула (11) показывает, что потери
определяются совместно загрузкой и размером буфера: при `ρ = 0,9` и `K = 20`
потери составляют 1,37 %, а при `K = 100` — 2,66·10⁻⁶. Это принципиально для
проверки Y.1541: один и тот же канал может проходить или не проходить класс
QoS в зависимости от выделенного буфера.

### 3.4 Изменение задержки IPDV

Для экспоненциального распределения времени пребывания в M/M/1 квантиль
уровня `1 − 10⁻³` равна:

```text
t_p = −ln(10⁻³) / (μ − λ) ≈ 6,9078 / (μ − λ)                      (12)
```

Поскольку минимальная задержка в модели пренебрежимо мала по сравнению с
квантилем, оценка IPDV звена:

```text
IPDV_e ≈ 6,9078 / (μ − λ)                                         (13)
```

При `ρ → 1` величина (13) неограниченно растёт, что согласуется с физикой
перегрузки.

### 3.5 Численный пример

Для `C = 100 Мбит/с`, `L = 12 000 бит`, `μ = 8333,33 пакета/с`,
`1/μ = 0,12 мс`, `K = 20`:

| ρ | IPTD_e − d0, мс | IPLR_e | IPDV_e, мс |
|---:|---:|---:|---:|
| 0,30 | 0,171 | 2,44·10⁻¹¹ | 1,18 |
| 0,50 | 0,240 | 4,77·10⁻⁷ | 1,66 |
| 0,70 | 0,400 | 2,40·10⁻⁴ | 2,76 |
| 0,80 | 0,600 | 2,33·10⁻³ | 4,15 |
| 0,90 | 1,200 | 1,37·10⁻² | 8,29 |
| 0,95 | 2,400 | 2,72·10⁻² | 16,58 |
| 0,98 | 6,000 | 3,86·10⁻² | 41,45 |
| 0,99 | 12,000 | 4,30·10⁻² | 82,89 |

Пусть путь состоит из пяти таких звеньев с `d0 = 2 мс` и `ρ = 0,7`.
Тогда:

```text
IPTD_path = 5 · (2 + 0,4) = 12 мс
IPLR_path = 1 − (1 − 2,395·10⁻⁴)^5 ≈ 1,196·10⁻³
IPDV_path ≈ sqrt(5) · 2,763 ≈ 6,18 мс
```

Путь проходит по IPTD (12 мс < 400 мс) и IPDV (6,18 мс < 50 мс), но
формально не проходит класс 1 по IPLR: 1,196·10⁻³ > 1·10⁻³. Этот пример
показывает, почему при проектировании недостаточно проверять только среднюю
задержку: накопление потерь по пути является самостоятельным ограничением.

## 4. Адаптация глобальной эффективности

### 4.1 Классическая метрика

В теории сложных сетей глобальная эффективность:

```text
E_glob(t) = 1/(N(N−1)) · Σ_{i≠j} 1 / d_ij(t)                      (14)
```

где `d_ij` — кратчайшее расстояние между вершинами `i` и `j`;
недостижимые пары дают нулевой вклад.

### 4.2 Физическая эффективность

В модели расстояние заменяется физической задержкой пути `IPTD_ij(t)`,
рассчитанной по (1) и (9) на текущих загрузках:

```text
E_phys(t) = 1/(N(N−1)) · Σ_{i≠j} 1 / IPTD_ij(t)                    (15)
```

Метрика (15) имеет размерность 1/с, поэтому используется нормированная
величина:

```text
E_phys_norm(t) = min(1, E_phys(t) / E_phys(0))                     (16)
```

Ограничение сверху единицей отражает смысл индекса сохранённого потенциала:
деградировавшая сеть не может быть «лучше» исходной. Без ограничения
возникает артефакт: при сильной перегрузке базовой сети `E_phys(0)` мала, и
после отказов отношение может превысить единицу.

### 4.3 QoS-эффективность

Главная метрика ВКР — нормированная глобальная эффективность с фильтром
требований Y.1541:

```text
E_QoS(t) = 1/(N(N−1)) · Σ_{i≠j} [ 1 / IPTD_ij(t) ] · I_ij(t)       (17)
E_QoS_norm(t) = min(1, E_QoS(t) / E_QoS(0))                        (18)
```

где `I_ij(t) = 1`, если путь `i → j` достижим и удовлетворяет (5) для
выбранного класса QoS, иначе 0.

Смысл (17): пара, не выполнившая SLA, не вносит вклад в коммуникационный
потенциал, даже если топологически путь существует. Это устраняет
недостаток классической `E_glob`, которая считает «почти working» путь
полноценным.

Дополнительные показатели:

```text
Q(t)   = 1/(N(N−1)) · Σ_{i≠j} I_ij(t)          — доля пар с выполненным QoS
R(t)   = (число достижимых пар) / (N(N−1))     — топологическая достижимость
Q|R(t) = Q(t) / R(t)                            — доля QoS среди достижимых
```

Разделение `Q`, `R` и `Q|R` позволяет различить два механизма деградации:
фрагментацию сети (падает `R`) и перегрузку/потери (падает `Q|R` при
высоком `R`).

### 4.4 Взвешенная живучесть

Для учёта бизнес-ценности узлов используется метрика НИР:

```text
LCC(t) = |V_LCC(t)| / N                                           (19)
φ_w(t) = Σ_{i ∈ V_LCC(t)} w_i / Σ_{i ∈ V} w_i                     (20)
```

где `V_LCC(t)` — наибольшая связная компонента подграфа работоспособных
узлов. В отличие от прежней реализации, `φ_w` рассчитывается именно по LCC,
как и определено формулой (2.3) НИР; это исключает ситуацию, когда
изолированные, но работающие узлы дают высокую «живучесть».

## 5. Распределение трафика All-to-All

### 5.1 Матрица спроса

Базовая интенсивность пары «источник–получатель» — `b` бит/с. Суммарный
спрос при `N` узлах:

```text
B_total = N(N−1)b                                                 (21)
```

При отказе часть узлов выбывает. Чтобы не занижать нагрузку на выжившую
сеть, используется режим сохранения суммарного трафика: при `A` активных
узлах интенсивность пары пересчитывается как

```text
b_A = b · N(N−1) / (A(A−1)),   A ≥ 2                              (22)
```

Это моделирует перераспределение трафика выбывших узлов на оставшиеся —
именно механизм возникновения заторов при отказах.

### 5.2 Итеративное равновесие

На каждой итерации `k`:

1. для каждой дуги вычисляется стоимость
   `c_e = IPTD_e(λ_e) + h`, где `h` — плата за транзит (по умолчанию 5 мс),
   подавляющая нефизичные обходные пути при насыщении;
2. для каждого активного источника запускается алгоритм Дейкстры;
3. весь спрос пары направляется по найденному кратчайшему пути;
4. нагрузки пересчитываются методом последовательных средних:

```text
λ_e^(k+1) = (1 − α_k) λ_e^(k) + α_k λ̃_e,   α_k = 1/(k+1)          (23)
```

Итерации повторяются 3–10 раз. Плата за транзит добавляется только к
стоимости выбора пути; фактическая IPTD пути считается суммой `IPTD_e` без
`h`, поэтому метрики (15)–(17) остаются физическими.

Алгоритм Дейкстры с двоичной кучей имеет сложность `O((V + E) log V)` на
один источник; полный пересчёт — `O(N (V + E) log V)` на итерацию.

## 6. Дискретно-событийная модель атак и восстановления

### 6.1 Поток атак

Атаки образуют пуассоновский поток с интенсивностью `λ_a`. Время до
следующей атаки — `Exp(λ_a)`. Вектор атаки:

- **targeted** — узел с максимальной степенью (среди работоспособных);
- **random** — равновероятный выбор;
- **cascading** — равновероятный выбор среди соседей уже отказавших узлов
  (эпидемическое распространение).

Атака успешна с вероятностью `P_attack` узла; при успехе узел переходит в
состояние отказа.

### 6.2 Восстановление

Отказавший узел помещается в очередь. Пул из `repair_slots` бригад
обслуживает очередь:

1. диспетчер выбирает узел: FIFO — по времени отказа, Triage — по
   максимальному весу `w_i` (при равенстве — по времени отказа);
2. если ресурсов `R` хватает на стоимость `C_repair`, они списываются,
   бригада занимается ремонтом в течение `Exp(μ_i)`;
3. по завершении ремонта узел восстанавливается с вероятностью
   `P_recovery`; при неудаче возвращается в очередь и требует новой попытки.

Triage стремится максимизировать `φ_w`, но расходует ресурсы быстрее;
FIFO «слеп» к ценности узлов. Это создаёт содержательный компромисс,
исследуемый в сценарии `strategy`.

### 6.3 Сэмплирование метрик

Метрики фиксируются на равномерной сетке `t_i = iT/(S−1)`. События
обрабатываются в порядке времени; при изменении состояния узлов
пересчитываются загрузки и матрица путей. Между событиями метрики не
меняются, поэтому пересчёт выполняется только при изменении состояния —
это существенно ускоряет Монте-Карло.

## 7. Статистическая обработка

Для `M` независимых прогонов вычисляется среднее и 95 % доверительный
интервал по t-распределению Стьюдента:

```text
CI = t_{0,975, M−1} · s / sqrt(M)                                 (24)
```

Различия стратегий проверяются непараметрическим U-критерием
Манна–Уитни; при множественных сравнениях применяется поправка Холма:

```text
p_holm[k] = min(p[k] · (m − k), 1),   p_holm[k] = max(p_holm[k], p_holm[k−1])  (25)
```

Гипотеза отвергается при `p_holm < 0,05`. Воспроизводимость обеспечивается
детерминированным `std::mt19937_64` с сидом, зависящим от номера прогона.

## 8. Выводы по этапу

1. Пороговые значения Y.1541 формализованы в виде таблицы классов 0–7;
   для модели выбраны проверки IPTD, IPLR и IPDV, а IPER/IPRR отнесены к
   не моделируемым факторам.
2. Получена замкнутая связь физических параметров канала с задержкой и
   потерями на основе M/M/1(K); показано, что буфер и загрузка совместно
   определяют выполнение IPLR.
3. Классическая глобальная эффективность адаптирована к физическим
   задержкам; введена QoS-эффективность `E_QoS`, учитывающая только пути,
   прошедшие SLA, и раздельные показатели достижимости `R`, `Q` и `Q|R`.
4. Разработан итеративный алгоритм All-to-All с Дейкстрой и MSA,
   моделирующий заторы при перераспределении трафика.
5. Построена дискретно-событийная модель атак и восстановления с
   FIFO/Triage, позволяющая исследовать компромисс «взвешенная живучесть —
   расход ресурсов».
6. Все соотношения реализованы в C++-ядре и проверены модульными тестами
   (78 проверок), а также численными экспериментами.
