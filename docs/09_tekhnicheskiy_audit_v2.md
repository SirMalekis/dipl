### 2.1 Точные структуры

### 2.2 Роли и гетерогенные параметры

`n_servers = max(1, int(N·0,15))`, `n_switches = max(1, int(N·0,20))`.
Узлы сортируются по убыванию текущей степени; первые `n_servers` —
server, следующие `n_switches` — switch, остальные — host.

При `heterogeneous=true`:

```text
P_attack   = clamp(profile.P_attack  · (base_P_attack/0,60)  ± 0,05, 0, 1)
P_recovery = clamp(profile.P_recovery· (base_P_recovery/0,80)± 0,05, 0, 1)
mu         = clamp(profile.mu        · (base_mu/0,20)        ± 0,02, 0,01, 1)
C_repair   = round(profile.C_repair  · base_C_repair)
weight     = profile.weight          · base_weight
```

Шум `jitter` не выходит за границы: при `base=0` или `base=1` разброс
равен нулю. Это устраняет прежнюю проблему, когда `P_recovery=0`
заменялось на 0,01.

При `heterogeneous=false` используются абсолютные
`base_P_attack`, `base_P_recovery`, `base_mu`, `base_C_repair`,
`base_weight` с шумом ±0,05/±0,01 и клампом 0..1.

**Остаётся особенность:** в star-топологии хаб — server, но ещё 6 из 7
«серверов» являются листьями степени 1 (tie по `id`). Это влияет на
`weight` и Triage; в отчёте это указано как свойство эвристики ролей,
а не ошибка кода.

### 2.3 Ёмкости и задержки рёбер

- `Edge::capacity=1,0·10⁹`, `base_latency=0,001` с в структуре;
- `TopologyParams` задаёт access 1,0·10⁹, core 10,0·10⁹,
  base latency 2 мс, jitter 1 мс;
- задержка ребра выбирается один раз:
  `lat = max(1e-6, base_latency + U(−jitter, +jitter))`;
- **star, ring, full_mesh** используют только `core_capacity`;
  `access_capacity` для них не влияет;
- **ER/BA**: после генерации
  `min(deg(u),deg(v)) ≥ 1,10·⟨k⟩` → `core_capacity`, иначе
  `access_capacity`;
- у ребра нет вероятности отказа, состояния up/down, приоритета или
  отдельной очереди. Отказывают только узлы.

### 2.4 Динамические веса и M/M/1(K)

Для дуги при текущей загрузке `load`:

```text
L  = packet_bits = 12 000 бит
μ  = C / L                       [пакетов/с]
λ  = load / L                    [пакетов/с]
ρ  = λ / μ = load / C
```

Условие устойчивости `ρ < 1` (в коде `ρ < 1 − 10⁻¹²`).
При `C ≤ 0` или `ρ ≥ 1 − 10⁻¹²`:

```text
saturated = true
IPTD_e = kSaturatedDelay = 1,0·10⁶ с
IPLR_e = 1
IPDV_e = 0
```

Иначе:

```text
IPTD_e = base_latency + 1/(μ − λ)
IPLR_e = (1 − ρ)·ρ^K / (1 − ρ^(K+1)),  ρ ≠ 1
IPLR_e = 1/(K + 1),                    ρ = 1
IPDV_e = −ln(10⁻³)/(μ − λ) = 6,907755…/(μ − λ)
```

`K = max(1, buffer_packets)`, по умолчанию 100.
`IPDV_e` — верхняя граница квантиля `1−10⁻³`; базовая задержка и её
jitter в IPDV не входят.

Пересчёт:

- при каждом рассмотрении ребра в `runDijkstra` — `evaluateEdgeQos`;
- на каждой итерации MSA — после обновления `edge.load` при следующей
  Дейкстре;
- в `computeMetrics` веса не пересчитываются: используются `PairState`
  из `assignTraffic`.

Узловые `weight` статичны; динамических весов узлов нет.

### 2.5 Маршрутизация, отказы и MSA

`assignTraffic`:

1. Обнуляет `edge.load`.
2. Собирает активные узлы (`state==1`).
3. При `A<2` возвращает пустую матрицу.
4. При `preserve_total_demand`:
   `b_A = b · N(N−1) / (A(A−1))`; суммарный спрос сохраняется.
5. Для `k=0..traffic_iterations−1`:
   - `edge.load = load[id]`;
   - для каждого активного `src` — Дейкстра;
   - весь спрос `b_A` пары добавляется на рёбра пути;
   - MSA: `load_e ← (1−α)load_e + α·new_load_e`,
     `α = 1/(k+1)`; при k=0 α=1, затем 0,5, 0,333.
6. На финальных нагрузках снова Дейкстра и `RoutingMatrix`.

Стоимость пути:

```text
c_e = IPTD_e(load_e) + hop_penalty
```

`hop_penalty` по умолчанию **0,005 с** и добавляется **за каждое
пройденное ребро**; фактическая IPTD пути считается без него.
Это согласовано с `traffic.h` и `docs/01`.

Агрегация пути:

```text
IPTD_path = Σ_e IPTD_e
IPLR_path = 1 − Π_e (1 − IPLR_e)
IPDV_path = sqrt(Σ_e IPDV_e²)
```

`PairState.saturated` = фактическая задержка ≥ `0,5·kSaturatedDelay`
(5·10⁵ с). Перегруженные пути остаются `reachable`, но не `conforming`;
в средние IPTD/IPLR не входят.

При отказе узла:

- `state=0`;
- `assignTraffic` исключает его из активных;
- все инцидентные дуги не используются;
- на следующей точке сетки выполняется полный пересчёт трафика
  (не локальный BFS);
- отказов рёбер нет; отдельной ремаршрутизации при отказе ребра нет.

Метрики пересчитываются только при `dirty` (после отказа/ремонта).
Если событий между точками нет, обновляется только `time`.

### 2.6 Метрики

```text
LCC(t)   = |V_LCC(t)| / N
φ_w(t)   = Σ_{i∈V_LCC} w_i / Σ_{i∈V} w_i
E_phys(t)= 1/(N(N−1)) · Σ_{i≠j} 1/IPTD_ij(t)
E_QoS(t) = 1/(N(N−1)) · Σ_{i≠j} (1/IPTD_ij(t))·I_ij(t)
Q(t)     = conforming_pairs / (N(N−1))
R(t)     = reachable_pairs / (N(N−1))
Q|R(t)   = conforming_pairs / reachable_pairs
E_phys_norm = min(1, E_phys/E_phys(0))
E_QoS_norm  = min(1, E_QoS/E_QoS(0))
```

`I_ij=1`, если путь достижим и `IPTD≤IPTD_K`, `IPLR≤IPLR_K`,
`IPDV≤IPDV_K` (для определённых требований). `IPER` не входит.

`MetricsContext::calibrate` использует полный `N(N−1)`, а не число
активных пар. `computeMetrics` считает `iptd_mean_ms`, `iplr_mean`,
`ipdv_mean_ms` только по достижимым несатурированным путям;
`iptd_p95_ms` — 95-й перцентиль; `avg_utilization`/`max_utilization` —
по активным **направленным** дугам.

**Важное свойство:** в базовой серии при классе 1 все достижимые пути
проходят SLA (`Q|R=1`), поэтому `E_QoS` численно совпадает с `E_phys`
(у ER различие 1,36·10⁻⁴). Это не ошибка формулы, а свойство
эксперимента; QoS-фильтр проявляется в stress-сценарии
(ER IPLR=2,608·10⁻³, ring=7,48·10⁻⁴).

### 3.3 Проверка пути

```cpp
iptd_ok = !isDefined(req.iptd_s) || (reachable && delay_s <= req.iptd_s);
iplr_ok = !isDefined(req.iplr)   || (reachable && loss <= req.iplr);
ipdv_ok = !isDefined(req.ipdv_s) || (reachable && ipdv_s <= req.ipdv_s);
conforms = reachable && iptd_ok && iplr_ok && ipdv_ok;
```

IPER не проверяется. Класс QoS — входное требование, а не состояние
сети: **автоматических переходов 1→3→5 нет**; для выбранного класса
проверяется каждый путь, затем считаются `Q`, `R`, `Q|R`, `E_QoS`.
IPER/IPRR не моделируются.

### 3.4 Классы в экспериментах

пар по классам в CSV нет. `run_meta` хранит только `qos_requirement`
выбранного класса.

## 4. Генерация многосвязных топологий

### 4.1 Список

```text

```

Watts–Strogatz, конфигурационная модель, геометрический граф и др. **не
реализованы**.

### 4.2 Erdős–Rényi G(N,p)

```text
prob = clamp(er_p, 0, 1)
для i=0..N−1:
  для j=i+1..N−1:
    если U(0,1) <= prob: addBidirectional(i,j,core_cap,lat)
ensureConnected(g, core_cap, lat)
```

- `er_p` по умолчанию 0,10; `N=50`;
- `ensureConnected` BFS-ом находит компоненты и соединяет первую с
  первыми вершинами остальных; фактический граф — **не чистый G(N,p)**;
- теория: `E[E]=pN(N−1)/2=122,5`, `⟨k⟩=p(N−1)=4,9`;
- факт (seed 42): **E=101**, `⟨k⟩=4,04`, `k_max=8`, `CV=0,487311`,
  `C=0,097015`, `L=2,817959`, `D=5`, `r=−0,290382`,
  `γ_est=1,992871`.

### 4.3 Barabási–Albert

```text
m  = max(1, min(ba_m, N−1))
m0 = max(m+1, 3); если m0 > N: m0 = N
начальное ядро — полный граф на m0 вершинах
repeated = [i повторён degree(i) раз]
для v=m0..N−1:
    targets = m различных вершин из repeated
    для t in targets:
        addBidirectional(v,t,core_cap,lat)
        repeated.push(v); repeated.push(t)
ensureConnected(...)
```

- `m=2`, `m0=3`; выбор цели пропорционален степени;
- `guard<10000` защищает от зацикливания;
- `ensureConnected` может добавить рёбра и изменить степени;
- `assignCapacitiesByDegree` затем назначает access/core.

`C=0,086022`, `L=1,920816`, `D=2`, `r=−0,928203`,

## 5. Векторы атак и алгоритмы восстановления

### 5.1 Атаки

События: `Attack`, `RepairComplete`. Атакуются **только узлы**;
`Edge` не имеет состояния/вероятности отказа.

`selectAttackTarget`:

- `random` — равномерно из активных;
- `cascading` — активные соседи уже отказавших узлов (по направленным
  дугам; для двунаправленных — обычные соседи). Если `exposed` пуст,
  выбирается любой активный. Это топологическая каскадность, не
  перегрузка;
- `targeted` — узел с максимальной **текущей степенью**; tie — случайно.
  `Node::weight`, `Edge::load`, центральность и тип узла не учитываются.

Успех: `U(0,1) < P_attack`; при успехе `state=0`, `waiting.push`,
`dispatch`. Первая атака — `Exp(λ)` от t=0; следующая — `Exp(λ)` от
текущего времени. При `λ=0` атак нет.

### 5.2 Восстановление

- Пул `repair_slots`; очередь `waiting`; `in_repair`.
- `selectWaiting(available)` выбирает **лучший доступный по стоимости**
  узел:
  - FIFO — минимальный `failure_time`, tie — меньший `id`;
  - Triage — максимальный `Node::weight`, tie — меньший `failure_time`.
  - Узлы с `C_repair > available` пропускаются, поэтому дорогой server
    не блокирует дешёвые switch/host.
- Если доступных нет, но есть ожидающие — `resource_exhausted=true`.
- Стоимость списывается, слот занимается, ремонт — `Exp(μ)`.
- После ремонта: `U(0,1) < P_recovery` → `state=1`, success++;
  иначе failed++, узел снова в `waiting`, `failure_time=now`.
- Ресурсы не пополняются; при неудаче стоимость не возвращается.
- Средняя очередь/занятые слоты — точные интегралы по времени:
  `area += size·Δt`, `mean=area/T`.

Стратегии: только `fifo` и `triage`; QoS-aware/centrality-aware
стратегий нет. Triage использует статический вес
`server=10/switch=5/host=1`.

### 5.3 Изменилось ли по сравнению с базовой версией

- Атаки по-прежнему только узловые.
- `targeted` по-прежнему по степени, без веса/загрузки.
- `cascading` по-прежнему по соседям отказавших, без нагрузки.
- Восстановление: только FIFO/Triage; новых стратегий нет.
- **Исправлено:** head-of-line blocking и гетерогенные параметры.

## 8. Текущие ограничения и замечания

Критических ошибок, ломающих сборку/запуск/основные сценарии, на момент
аудита не обнаружено: сборка, 82 теста, CLI-smoke, selftest, GUI
self-test и demo проходят. Остаются **ограничения модели и
сознательные упрощения**:

1. **IPER/IPRR не моделируются.** Таблица Y.1541 хранит пороги, но
   `PathQos` проверяет только IPTD/IPDV/IPLR; README/документация это
   явно указывают.
2. **Нет автоматических переходов класса QoS.** Класс фиксирован на
   прогон; проверяется соответствие путей выбранному классу.
3. **Атакуются только узлы.** `Edge` не имеет состояния отказа;
   каскадность — топологическая (соседи отказавших), без перегрузки.
4. **Нет node-link визуализации графа.** GUI показывает агрегированные
   метрики, bar chart, CCDF и таблицы; отказавшие узлы/загрузка рёбер
   на схеме не отображаются.
5. **`access_capacity` влияет только на ER/BA.** star/ring/full_mesh
   используют `core_capacity`.
6. **`ensureConnected` может добавлять рёбра в ER/BA.** Фактический ER —
   не чистый G(N,p); это отражено в docs/05/08.
7. **Роли server/switch/host — эвристика по степени.** В star 6 из 7
   серверов могут быть листьями; это влияет на веса/Triage.
8. **`Graph::num_edges` — дуги, `TopologyStructure::num_edges` —
   уникальные неориентированные рёбра.** В CSV `edges` второе.
9. **`hop_penalty` — за каждое ребро**, а не за промежуточный узел; так
   и задокументировано.
10. **E_QoS в базовой серии совпадает с E_phys** из-за `Q|R=1`; это
    свойство эксперимента, а не ошибка формулы. Stress показывает
    работу QoS-фильтра; в тестах есть случай `E_QoS=0` при `E_phys>0`.
11. **Нет распределения по классам QoS**: все 7 конфигов — класс 1,
    отдельного sweep по `qos_class` нет.
12. **Нет пошагового режима GUI**: только потоковый прогресс/журнал,
    затем чтение CSV.
13. **`requirements.txt` задаёт диапазоны, а не lock-файл**; точные
    версии зафиксированы только в этом отчёте.
14. **Статистика:** U-тест асимптотический (с tie-коррекцией и
    continuity correction); для очень малых выборок p-значения
    приблизительны. Strategy/attack p-values скорректированы Холмом;
    topology — тоже.
