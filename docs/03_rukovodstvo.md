# Руководство пользователя

## 1. Требования

- Windows 10/11, Visual Studio 2022/2026 с компонентом C++;
- Python 3.11+;
- Python-пакеты: `customtkinter`, `matplotlib`, `pandas`, `Pillow`.

```powershell
python -m pip install customtkinter matplotlib pandas Pillow
```

## 2. Сборка ядра

```powershell
.\build.ps1
```

или вручную:

```powershell
msbuild netsim.vcxproj /p:Configuration=Release /p:Platform=x64
```

Появится `x64\Release\netsim.exe`. Если файл лежит в другом месте, задайте
переменную окружения:

```powershell
$env:NETSIM_EXE = "D:\netsim\netsim.exe"
```

## 3. Запуск GUI

```powershell
python run_gui.py
```

Окно состоит из бокового меню и трёх страниц.

### 3.1 Страница «Параметры»

Секции:

1. **Сценарий и топология** — постановка эксперимента и набор топологий.
   Для ER задаётся вероятность ребра `p` (`⟨k⟩ = p(N−1)`), для BA — число
   связей нового узла `m` (теоретически `γ ≈ 3`, `⟨k⟩ ≈ 2m`).
2. **Масштаб моделирования** — число узлов, прогонов МК, горизонт, число
   точек временного ряда, seed.
3. **Деструктивные воздействия** — стратегия и интенсивность атак,
   вероятность успеха.
4. **Восстановление** — диспетчер FIFO/Triage, число бригад, ресурсы,
   вероятность и скорость ремонта.
5. **Качество обслуживания** — класс Y.1541, трафик на пару, размер пакета,
   буфер.
6. **Каналы и нагрузка** — пропускная способность доступа/ядра, базовая
   задержка, режим сохранения трафика, итерации MSA, плата за транзит.
7. **Генератор топологии** — гетерогенность, вероятность ER, число связей BA,
   джиттер задержки.
8. **Параметрический анализ** — диапазоны для сценария `sweep`.

Кнопки внизу:

- **Запустить** — собрать `config.ini`, запустить `netsim.exe`, показать
  прогресс и журнал;
- **Остановить** — завершить процесс;
- **Открыть каталог** — открыть папку прогона в Проводнике.

После успешного завершения приложение автоматически переходит на страницу
результатов.

### 3.2 Профили нагрузки

| Профиль | Трафик на пару | Доступ | Ядро | Буфер |
|---|---:|---:|---:|---:|
| Базовая | 2 Мбит/с | 1 Гбит/с | 10 Гбит/с | 100 |
| Перегрузка | 20 Мбит/с | 100 Мбит/с | 1 Гбит/с | 50 |
| Стресс | 100 Мбит/с | 100 Мбит/с | 1 Гбит/с | 20 |

Профиль «Стресс» удобен для демонстрации нарушения IPLR: при 20 пакетах
буфера и загрузке выше 0,75 потери превышают 10⁻³.

### 3.3 Страница «Результаты»

Сверху — выбор прогона, кнопки «Обновить» и «PNG». Карточки показывают:

- **E_QoS** — средняя нормированная QoS-эффективность;
- **Доля пар с QoS** — `Q`, процент пар, выполнивших SLA;
- **LCC** — доля наибольшей связной компоненты;
- **φ_w** — взвешенная живучесть;
- **IPTD, мс** — средняя задержка;
- **IPLR** — максимальная средняя вероятность потерь.

Вкладки:

- **Динамика** — временные ряды; выбор топологии в выпадающем списке.
- **Топологии** — бары E_QoS / Q / LCC / φ_w с 95 % ДИ.
- **Sweep** — кривые E_QoS от λ, R, μ, P_attack.
- **Атаки** — сравнение targeted / random / cascading.
- **FIFO/Triage** — переключение E_QoS / φ_w; звёздочка — значимое
  преимущество Triage (p < 0,05).
- **Сводка** — компактные таблицы по сценарию (топологии, sweep,
  FIFO/Triage, атаки, временные ряды, структура).
- **Данные** — все CSV прогона в табличном виде, копирование и экспорт.
- **Структура** — таблица метрик выбранной топологии (степени, кластеризация,
  длина пути, диаметр, ассортативность, γ) и CCDF распределения степеней.

Кнопка **PNG** сохраняет текущий график. Кнопка **«Таблицы»** открывает
вкладку «Данные» со всеми CSV прогона; на каждой вкладке есть кнопка
**«Таблица»**, открывающая соответствующий файл.

## 4. Сценарии

### 4.1 Сравнение топологий

Параметры: 5 топологий, `n_sims` прогонов, `T`, λ, R, бригады, класс QoS.
Результат: `topology_comparison.csv` и `topology_significance.csv`.
Ожидаемая картина: полносвязная сеть устойчивее; звезда катастрофична при
целевой атаке на хаб; кольцо чувствительно к разрывам, но локализует
каскады.

### 4.2 Параметрический анализ

Выберите `scenario = Параметрический анализ`; диапазоны задаются тройкой
`MIN MAX ТОЧЕК`. Для каждой точки выполняется полный Монте-Карло.
Результат: `sweep_<param>.csv`.

### 4.3 FIFO vs Triage

Задайте уровни ресурсов, например `20,40,80,150`. Ядро прогоняет обе
политики при каждом `R`. Значимость считается отдельно по E_QoS и φ_w.
При дефиците ресурсов Triage обычно повышает φ_w, но чаще исчерпывает пул.

### 4.4 Векторы атак

Отметьте `targeted`, `random`, `cascading`. Результат:
`attack_vector_analysis.csv`.

### 4.5 Временные ряды

Одна реализация на топологию; полезно для отладки и иллюстрации динамики.
Результат: `timeseries_<topo>.csv` и `run_meta_<topo>.csv`.

### 4.6 Структурный анализ ER/BA

Сценарий `structure` не запускает симуляцию: он генерирует графы и считает
структурные метрики. Для каждого прогона файлы `topology_structure.csv` и
`topology_degrees_<topo>.csv` создаются автоматически, поэтому вкладка
«Структура» доступна и для обычных сценариев. Подробное описание моделей —
в [docs/05_topolologii.md](05_topolologii.md).

### 4.7 Полная демонстрация

Сценарий `demo` за один компактный прогон заполняет все вкладки:
динамику, топологии, sweep, атаки, FIFO/Triage, структуру и данные.
Это рекомендуемый способ проверить все возможности. Подробнее об именах
прогонов и таблицах — в [docs/06_zapuski_i_dannye.md](06_zapuski_i_dannye.md).

## 5. Пакетный режим

```powershell
# Сравнение топологий
.\x64\Release\netsim.exe run --scenario topology `
    --topologies star,ring,full_mesh,erdos_renyi,barabasi_albert `
    --num-nodes 50 --sims 30 --T 150 --lambda 1.0 `
    --resources 200 --slots 3 --qos-class 1 `
    --out results\base --progress

# Стресс по потерям
.\x64\Release\netsim.exe run --scenario timeseries `
    --topology full_mesh --num-nodes 10 --sims 1 --T 20 `
    --lambda 0 --demand 90000000 --access 100000000 --core 100000000 `
    --buffer 20 --qos-class 1 --out results\loss --progress

# Повтор последней конфигурации
.\x64\Release\netsim.exe run --quick

# Только структурный анализ ER/BA
.\x64\Release\netsim.exe run --scenario structure `
    --topologies erdos_renyi,barabasi_albert `
    --num-nodes 100 --er-p 0.05 --ba-m 2 `
    --out results\structure
```

Основные опции:

```text
--scenario topology|sweep|strategy|attack|timeseries|structure|demo|all
--config <path>          загрузить INI
--out <dir>              каталог результатов
--topology <name>        одна топология
--topologies a,b,c       список
--num-nodes N --sims M --T X
--lambda L --resources R --slots S
--attack targeted|random|cascading
--gatekeeper fifo|triage
--qos-class 0..7 --demand BPS
--buffer K --access BPS --core BPS
--seed N --progress
```

`--quick` читает `results/last_config.ini`.

## 7. Интерпретация метрик

- **E_QoS_norm** стремится к 1, пока сеть сохраняет коммуникационный
  потенциал; падение ниже 0,5 означает потерю половины потенциала.
- **Q** — доля всех упорядоченных пар, выполнивших SLA. Для полностью
  исправной сети при базовой нагрузке ожидается 1,0.
- **R** — доля достижимых пар. Если `R` высока, а `Q` низка, причина —
  перегрузка/потери, а не фрагментация.
- **Q|R** — доля QoS среди достижимых; удобна для диагностики.
- **LCC** — структурная связность; **φ_w** — связность с учётом весов
  (сервер 10, коммутатор 5, хост 1).
- **IPTD** — средняя задержка путей без перегруженных звеньев.
- **IPLR** — средняя вероятность потерь; превышение порога класса означает
  нарушение SLA.

### Пример: потеря качества из-за буфера

Полносвязная сеть 10 узлов, ёмкость 100 Мбит/с, трафик 90 Мбит/с на пару,
буфер 20 пакетов, атак нет:

- `IPTD ≈ 3,13 мс` — класс 1 по задержке выполняется;
- `IPLR ≈ 1,37·10⁻²` — класс 1 по потерям нарушен;
- `Q = 0`, `E_phys_norm = 1`, `E_QoS_norm = 0`.

Это корректный результат: сеть связна и быстра, но не выполняет SLA по
потерям. Увеличение буфера до 100 пакетов снижает потери до 2,7·10⁻⁶ и
восстанавливает `Q ≈ 1`.

## 8. Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| «Ядро не найдено» | не собрано `netsim.exe` | `.\build.ps1` |
| `E_QoS_norm = 0` при `Q = 0` | базовая сеть не проходит QoS | уменьшить нагрузку, увеличить буфер/ёмкость, сменить класс |
| `IPLR = 0`, `Q` низка | фрагментация, а не потери | смотреть `R`, `LCC`, `φ_w` |
| Прогон долго не завершается | большое `n_sims × топологии × sweep` | уменьшить `n_sims`/точки |
| GUI не видит новый прогон | кэш списка | «Обновить» |
| Кириллица в CSV «кракозябрами» | Excel не распознал UTF-8 | импорт как UTF-8 или открыть в LibreOffice |

## 9. Горячие клавиши и советы

- `Enter` в полях — значения по умолчанию.
- Для быстрой проверки используйте `n_sims = 5…10`; для выводов — не менее
  30.
- При `n_sims < 10` доверительные интервалы широкие, а U-критерий имеет
  малую мощность.
- Для демонстрации Triage берите `R = 20…80`, `repair_slots = 2`,
  `λ = 1,5` и смотрите метрику **φ_w**.
