# Топологии ER и BA: назначение, генерация и структурный анализ

## 1. Зачем нужны модели случайного и безмасштабного графа

Топология сети определяет, как отказ одного узла влияет на связность всей
инфраструктуры. В работе используются две классические модели сложных сетей:

- **Эрдёша–Реньи (ER)** — однородный случайный граф, базовая («нулевая»)
  модель без выраженных хабов;
- **Барабаши–Альберта (BA)** — безмасштабная сеть с предпочтительным
  присоединением, воспроизводящая степенное распределение степеней и
  наличие хабов.

Они дополняют детерминированные топологии (звезда, кольцо, полносвязная
сеть) и позволяют отделить эффекты централизации от эффектов случайности и
гетерогенности степеней.

## 2. Модель Эрдёша–Реньи G(N, p)

### 2.1 Определение

Каждая из `N(N−1)/2` возможных неориентированных пар соединяется ребром
независимо с вероятностью `p`. Получается случайный граф `G(N, p)`.

Математическое ожидание числа рёбер:

```text
E[E] = p · N(N−1)/2
```

Средняя степень:

```text
⟨k⟩ = p · (N−1)
```

Распределение степени вершины — биномиальное `Bin(N−1, p)`; при больших `N`
и фиксированном `⟨k⟩` оно приближается распределением Пуассона:

```text
P(k) ≈ e^(−⟨k⟩) · ⟨k⟩^k / k!
```

Коэффициент кластеризации в модели близок к `p`, то есть к вероятности того,
что два соседа данной вершины соединены между собой.

Порог появления гигантской компоненты:

```text
p_c ≈ 1/(N−1)
```

При `p > p_c` в графе существует компонента размера `O(N)`; при `p < p_c`
граф распадается на мелкие компоненты. Генератор в проекте дополнительно
гарантирует связность, добавляя рёбра остовного дерева, если случайный граф
получился несвязным.

### 2.2 Назначение

ER — это **нулевая гипотеза**: сеть без выделенных хабов, в которой все узлы
статистически равноправны. Она нужна для ответа на вопрос: является ли
наблюдаемая устойчивость следствием топологии или случайности? ER также
моделирует однородные случайные отказы и сети, где все узлы имеют примерно
одинаковую степень.

### 2.3 Параметры и реализация

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `N` | число узлов | 50 |
| `p` (`er_p`) | вероятность ребра | 0,10 |
| `seed` | воспроизводимость | 42 |

Алгоритм:

```text
для i = 0 .. N−1:
    для j = i+1 .. N−1:
        если U(0,1) ≤ p: добавить двунаправленное ребро i—j
если граф несвязен: соединить компоненты рёбрами от первой компоненты
```

### 2.4 Ограничения

- степени распределены узко, хабов нет;
- целевая атака на «самый важный» узел почти не отличается от случайной;
- кластеризация и модульность не соответствуют многим реальным сетям;
- модель не учитывает географию, стоимость связей и иерархию.

## 3. Модель Барабаши–Альберта

### 3.1 Определение и алгоритм

Сеть строится инкрементально:

1. создаётся начальное ядро из `m0 = max(m+1, 3)` узлов, соединённых
   полносвязно;
2. каждый новый узел присоединяется к `m` различным существующим узлам;
3. вероятность выбрать узел `i` пропорциональна его текущей степени:

```text
Π(i) = k_i / Σ_j k_j
```

Это механизм **предпочтительного присоединения**: «богатые становятся
ещё богаче», и в сети появляются хабы.

В реализации используется список `repeated_nodes`, в котором каждый узел
повторяется пропорционально своей степени; случайный выбор из этого списка
даёт требуемое распределение.

### 3.2 Свойства

Для больших `N` распределение степеней имеет степенной вид:

```text
P(k) ~ k^(−γ),  γ ≈ 3
```

Средняя степень:

```text
⟨k⟩ ≈ 2m
```

Следствия:

- **хабы**: максимальная степень может в десятки раз превышать среднюю;
- **короткие пути**: диаметр растёт как `O(log N / log log N)`, сеть
  «тесного мира»;
- **дисассортативность**: хабы соединяются преимущественно с
  низкостепенными узлами (`r < 0`);
- **уязвимость к целевым атакам**: удаление нескольких хабов фрагментирует
  сеть, тогда как случайные отказы переносятся хорошо.

Кластеризация BA зависит от `m` и `N`; при малых `m` она сравнима с ER или
ниже, но наличие хабов и коротких путей остаётся ключевым отличием.

### 3.3 Назначение

BA используется как модель реальных инфраструктур с выраженными центрами:
магистральные маршрутизаторы, контроллеры домена, серверы баз данных,
популярные сервисы. Именно на таких сетях проверяется риск-ориентированное
восстановление Triage: потеря хаба дороже потери периферийного хоста.

### 3.4 Параметры и реализация

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `N` | число узлов | 50 |
| `m` (`ba_m`) | число связей нового узла | 2 |
| `seed` | воспроизводимость | 42 |

При `m = 2` сеть особенно хрупка: большинство узлов имеет степень 2, а вся
связность держится на нескольких хабах. При `m = 3–4` появляется больше
резервных путей, и устойчивость к целевым атакам заметно выше. Это
рекомендуется проверять параметрическим анализом.

### 3.5 Ограничения

- фиксированный показатель `γ ≈ 3` не всегда соответствует реальным сетям;
- нет старения узлов, «привлекательности» (fitness) и удаления связей;
- модель не воспроизводит сообщества и иерархическую модульность;
- начальное ядро и порядок добавления узлов влияют на малых `N`.

## 4. Структурные метрики

Для сравнения топологий программа вычисляет:

| Метрика | Обозначение | Смысл |
|---|---|---|
| Число узлов/рёбер | `N`, `E` | масштаб графа |
| Средняя степень | `⟨k⟩ = 2E/N` | плотность связей |
| Мин./макс. степень | `k_min`, `k_max` | наличие хабов |
| Коэффициент вариации | `CV = σ_k/⟨k⟩` | неоднородность степеней |
| Кластеризация | `C` | доля замкнутых троек |
| Средняя длина пути | `L` | среднее число хопов |
| Диаметр | `D` | максимальный кратчайший путь |
| Ассортативность | `r` | корреляция степеней концов рёбер |
| Компоненты | — | число компонент связности |
| Доля LCC | `|LCC|/N` | размер главной компоненты |
| Ожидаемая `⟨k⟩` | — | по параметрам модели |
| Наклон CCDF | — | линейная регрессия `ln P(K≥k)` |
| Оценка γ | — | оценка Хилла при `x_min = 2` |

Кластеризация вычисляется как отношение числа замкнутых троек к общему
числу троек:

```text
C = (Σ_u число пар соседей u, соединённых между собой) /
    (Σ_u k_u(k_u−1)/2)
```

Ассортативность — коэффициент корреляции Пирсона для степеней концов рёбер:

```text
r = [Σ_e j_e k_e / E − ((Σ_e (j_e+k_e))/(2E))²] /
    [Σ_e (j_e²+k_e²)/(2E) − ((Σ_e (j_e+k_e))/(2E))²]
```

Оценка Хилла:

```text
γ = 1 + n_tail / Σ_{k_i ≥ 2} ln(k_i / 1,5)
```

Она устойчивее линейной регрессии CCDF на малых выборках; для BA при
`N = 50`, `m = 2` даёт `γ ≈ 3,2`, что близко к теоретическому значению 3.

## 5. Результаты структурного анализа (N = 50)

| Топология | E | ⟨k⟩ | k_max | CV | C | L | D | r | γ |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| star | 49 | 1,96 | 49 | 3,46 | 0,000 | 1,96 | 2 | −1,000 | — |
| ring | 49 | 1,96 | 2 | 0,10 | 0,000 | 17,00 | 49 | −0,021 | — |
| full_mesh | 1225 | 49,00 | 49 | 0,00 | 1,000 | 1,00 | 1 | 0,000 | — |
| erdos_renyi | 101 | 4,04 | 8 | 0,49 | 0,097 | 2,82 | 5 | −0,290 | 1,99 |
| barabasi_albert | 97 | 3,88 | 37 | 1,94 | 0,086 | 1,92 | 2 | −0,928 | 3,19 |

Ключевые различия ER и BA при близкой средней степени:

- максимальная степень: **8 против 37** — в BA есть выраженные хабы;
- коэффициент вариации: **0,49 против 1,94** — степени BA неоднородны;
- средняя длина пути: **2,82 против 1,92** — BA компактнее;
- ассортативность: **−0,29 против −0,93** — BA резко дисассортативен;
- оценка γ: **1,99 против 3,19** — у BA степенной хвост.

## 6. Влияние на живучесть и QoS

В базовом сценарии ВКР (`N = 50`, `λ = 1,0`, `R = 200`, класс QoS 1):

| Топология | E_QoS | Q | LCC | φ_w |
|---|---:|---:|---:|---:|
| erdos_renyi | 0,406 | 0,477 | 0,625 | 0,425 |
| barabasi_albert | 0,114 | 0,122 | 0,187 | 0,213 |

ER-граф устойчивее BA при целевых атаках: в BA удаление нескольких хабов
фрагментирует сеть, тогда как в ER все узлы статистически равноправны.
Однако BA компактнее и при случайных отказах может сохранять связность
дольше; это зависит от `m`, числа бригад и ресурсов. Поэтому в работе
исследуются оба класса сетей, а не только «хорошая» или «плохая» модель.

При `m = 2` BA особенно уязвим; увеличение `m` до 3–4 добавляет резервные
пути и должно повышать E_QoS. Это направление параметрического анализа.

Отдельный результат связан с политикой восстановления. В BA Triage значимо
повышает φ_w уже при R = 40 и даёт E_QoS 0,045 против 0,033 у FIFO при
R = 150 (p ≈ 0,03). В ER, наоборот, различия незначимы (p = 0,57–0,99):
серверы не закреплены за топологически уникальными хабами, поэтому
приоритизация по весу не даёт выигрыша. Это показывает, что эффективность
Triage зависит от топологии, а не является универсальной.

По векторам атак BA ведёт себя как ослабленная звезда: targeted-атака даёт
E_QoS 0,066 против 0,293 при random. ER значительно устойчивее к выбору
вектора: 0,253 / 0,308 / 0,338 для targeted / random / cascading.

## 7. Как использовать

### GUI

1. На странице «Параметры» отметьте `Эрдёш–Реньи` и/или
   `Барабаши–Альберт`.
2. Задайте `ER: вероятность p` и `BA: связей m` в секции генератора.
3. Запустите любой сценарий: `topology`, `sweep`, `strategy`, `attack`,
   `timeseries`.
4. Вкладка **«Структура»** покажет таблицу метрик и CCDF распределения
   степеней для выбранной топологии.

### CLI

```powershell
# Только структурный анализ
.\x64\Release\dipl.exe run --scenario structure `
    --topologies erdos_renyi,barabasi_albert `
    --num-nodes 100 --er-p 0.05 --ba-m 2 `
    --out results\structure

# Полный сценарий с ER/BA
.\x64\Release\dipl.exe run --scenario topology `
    --topologies star,ring,full_mesh,erdos_renyi,barabasi_albert `
    --num-nodes 50 --sims 30 --T 150 --out results\base
```

### Файлы

- `topology_structure.csv` — сводная таблица метрик;
- `topology_degrees_<topology>.csv` — гистограмма степеней;
- `config.ini` — параметры `er_p`, `ba_m`, `seed`.

## 8. Выводы

1. ER и BA — не «ещё две картинки», а две разные гипотезы о структуре сети:
   однородная случайность и предпочтительное присоединение.
2. Структурный анализ подтверждает различие: BA имеет хабы (k_max 37 против
   8), высокую неоднородность (CV 1,94 против 0,49), короткие пути и
   степенной хвост (γ ≈ 3,2).
3. Это различие напрямую влияет на живучесть: ER устойчивее к целевым
   атакам, BA — компактнее, но хрупок при потере хабов.
4. Обе модели поддержаны во всех сценариях, GUI и CLI; структурный анализ
   экспортируется автоматически и доступен на отдельной вкладке.
